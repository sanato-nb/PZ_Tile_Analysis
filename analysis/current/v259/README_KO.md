## 큰 PNG 예외를 처리한 방식

- 일반 2x PNG: 기본 128×256 픽셀 격자.
- 원본 정의가 별도의 너비·높이를 명시하고 PNG 픽셀 크기가 그 격자에 정확하게 나누어지면 **원본 정의의 논리적 셀 수를 우선**.
- JUMBO/JUMBOXL/JUMBOXXL 나무 PNG 33개는 원본 정의상의 **516개 논리 슬롯**으로 묶음. 별도의 그루터기 PNG 2개는 **384개 슬롯**으로 기록되어, 두 종류를 합하면 **900개 슬롯**임.
- 루트 `Tiles/vegetation_foliage_01.png`의 16×16 기본 격자 대신 원본 정의의 8×8에 맞춰 64셀로 처리.
- 원본 타일셋 이름을 찾지 못한 PNG 5종은 임의 Local ID 부여를 보류함.

이 규칙은 정해진 격자 기준의 **기계적 출처 연결**이며 개별 물체의 그림 정체·구성 부품·게임 내 TileZed 맵핑을 자동 인증하지 않는다.

## 어떤 파일을 쓰면 되나

- **PZ_v259_full_CSV.zip**: 모든 이미지 셀, PNG 크기, Local ID, 속성, 기존 분석, 충돌·미연결 내역을 담은 CSV 묶음.
- **PZ_v259_full_SQLite.zip**: SQLite 데이터베이스(원본 출처 7개, 슬롯 73,644행, 속성 195,265행, 논리 이미지 셀 47,796행). 압축 해제 후 SQLite DB Browser나 Python sqlite3로 조회.
- `ALL_PNG_GRID_CELLS.csv`: 이미지 격자 하나당 1행, 투명 셀 포함. `all_properties_json`은 해당 칸에서 우선순위 규칙으로 고른 속성 표시값.
- `SOURCE_SLOTS_NOT_LINKED_TO_PNG.csv`: 정의에는 있으나 정확한 PNG 대응을 확인하지 못한 슬롯.
- `SOURCE_PROPERTY_CONFLICTS.csv`: 출처 간 다른 속성 원문을 모두 보존.
- `PNG_FILE_GRID_AUDIT.csv`: PNG별 크기, 논리 격자, 출처 매핑 상태.
- `MANIFEST.json`: 실제 실행 결과 수량, SQLite 해시·무결성.

## 주의

원본 `CustomName`·`GroupName`은 사물·그룹 이름의 단서지만 특정 스프라이트가 완성된 가구 전체인지 다칸 부품인지 증명하지 못한다. `Facing`은 방향 단서, `SpriteGridPos`는 부품 배치 단서이다. 이미지에 보이는 34,090개는 **불투명/반투명 픽셀이 존재하는 논리 격자칸**이며 34,090개의 완결 물체를 뜻하지 않는다.

기존 v255 사용자 판정 68종·보류 439종과 이전 DB/PNG/TMX는 변경하지 않았다. 원본 출처 이름이 같은 경우에도 정의 우선순위 선택과 최종 객체 정체 인증은 별개다. v258은 고정 128×256 격자 기준의 과거 점검용이고 **v259가 원본 정의 크기를 반영한 권장 최신 카탈로그**다.
