**최신 사용자 지시:** 이전에 다른 실제 TMX 배치가 없어 별도 검수에서 제외했던 188종을 모두 재검수한다. **원본 이미지가 없거나 알파 전체가 0인 완전 투명 타일만 제외한다.**

**실제 검사 결과: 제외 대상 0.** 기존 v245의 RGBA 기록만 믿지 않고, v119에서 원본 아틀라스 PNG로부터 만든 **lossless A 크롭**을 다시 정확한 ZIP entry에서 열어 **188/188 PNG 파일 SHA·RGBA 픽셀 SHA·alpha 비투명 픽셀 수**, ZIP archive **10/10 SHA**를 재검증했다. 최소 비투명 픽셀 44개. 이번에는 **전체 원본 아틀라스 PNG 파일 자체의 SHA를 새로 계산하지 않았다.**

84개 원래 TMX(v246 전수 확인)에서 **188종 모두 실제로 딱 1번 배치**된 키들이므로, 만들어낸 다른 배치로 대체하지 않고 **그 유일한 배치 188곳에서** 원본 TMX SHA를 확인하고 원래 B와 타깃 raw GID **정확히 하나를 제거한 C**를 재렌더했다. B와 C는 별도 진단 화면이 아니라 동일 TMX·같은 층/레이어에 기반한다. 정확한 공식 게임 엔진 렌더·TileZed 출력 인증은 아니다.

## B−C=0이던 74종의 가림 확인

74종에서 타깃 A를 원래 순서로 그린 **직후에는 74/74 모두 픽셀 변화가 있었다.** 그다음 다른 스프라이트를 차례대로 그리면 가려지는 과정이 **350번** 발생했다.

- 같은 레이어의 뒤에 그려진 스프라이트만 영향을 준 키 **16종**.
- 뒤쪽 다른 레이어의 스프라이트만 영향을 준 키 **17종**.
- 같은 레이어와 다른 레이어 모두 영향을 준 키 **41종**.

따라서 74개의 B−C=0을 완전 투명, 원래 스프라이트가 비어 있음 또는 정체가 없다는 뜻으로 사용하면 안 된다. 추적은 **프로젝트 5×5 원본 TMX 재구성 렌더러의 그리기 순서**에 대한 것이고 실제 PZ 클라이언트의 공식 렌더 규칙 인증과는 구분한다. 진단상의 A를 마지막에 그린 사진은 **원래 B도, 사용자 정의 D도 아님**.
