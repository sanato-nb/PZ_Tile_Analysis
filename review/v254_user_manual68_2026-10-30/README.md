# v254 — 사용자 68종 직접 판정과 미선택=기존 잠정 후보 동의

**사용자 원문:** “선택안한거는 맞는거같아서 따로 체크안했어”.

v253 사용자 수동 검수기 68종 중 **선택하지 않은 항목 52종은 ‘기존 판정에 동의’**로 해석한다. 이는 **공식 게임 타일 Local ID 인증이나 TileZed 확정은 아니며**, 기존 v252 잠정 후보를 보존·우선 참조한다는 사용자 평가다.

## 업로드 원본 정확한 보존

- 제출 원본 파일명: `PZ_68종_사용자_수동검수_2026-10-30.csv`
- 원본 바이트: **44,865바이트**, BOM 포함 UTF-8 / CRLF.
- 업로드 SHA256: `93f28b76503458c895847a080bb9da78e4514c2de7a0e6fdece9e80992fb0d04`
- **[USER_UPLOADED_68_VERBATIM.csv](USER_UPLOADED_68_VERBATIM.csv)** — v253 빈 양식 + 사용자 비어 있지 않은 18행의 정확한 문자 그대로 재구성하고 **원본 SHA256이 100% 일치한 것만** GitHub에 기록. 공백/오탈자/끝 공백도 수정하지 않았다.
- **[USER_NONEMPTY_FIELDS_VERBATIM.json](USER_NONEMPTY_FIELDS_VERBATIM.json)** — 총 18행 중 실제 수정한 셀 원문과 원본 SHA/양식 Git blob 증거.

| 상태 | 수량 |
|---|---:|

- **[ALL68_USER_PRIORITY_PROVISIONAL_OVERLAY.csv](ALL68_USER_PRIORITY_PROVISIONAL_OVERLAY.csv)** — 68개 키의 기존 후보(v252 → 없으면 v251)와 새 사용자 입력의 **단독 우선순위 오버레이**. 기존 후보와 사용자 원문을 둘 다 보존한다. 판정 상태는 `user_explicit_identified`, `user_explicit_part_only`, `user_implicit_accept_prior_provisional` 중 하나. *인증과 다름*.
- 사용자가 `user_orientation_KO`에 쓴 문장(예: “수술용 의자 절반 치과같은곳에있는거 ”, “좌석(쇼파?) 뒷면 절반”)은 모델이 이름이나 공식 방향으로 바꾸지 않고 **원문 그대로 별도 컬럼**에 저장한다.
- 실제 지정 이름 `constructedobjects_01/18`: 사용자 **“쥐덫”**.
- 이전 A가 아주 작아 정체 불명이었던 `location_entertainment_theatre_01/174`: 사용자 **“모서리”** (부품까지만).
- `walls_garage_02/23`: 사용자 **“난간 손잡이 모서리”** (부품까지만).
- `appliances_cooking_01/10`, `furniture_storage_02/38`은 상태 선택은 없지만 부가 설명을 작성했으므로 **암묵적 기존 판정 동의 + 사용자 보충 설명**으로 처리했다.

## 적용 범위·안전 규칙

1. **사용자 새 문구 > 기존 AI 잠정 후보 > 파일명 기반 계열명** 순서로 *시각적 정체 표현에만* 우선순위를 준다. 사용자 입력이 없을 때만 기존 v252 후보, 없으면 v251 후보를 쓴다.
2. 사용자의 미선택은 **맞다고 보는 기존 잠정 설명의 승인**으로, *정체 불명·보류·확정 아님을 강제한 과거 사용자 지시를 뒤집거나 공식 인증으로 승격하지 않는다*.
3. v251, v252, v253 및 v240 마스터 전체10,042종 / 활성9,587종·비활성455종, 예전 수동80/제외14/33, 원본 PNG/TMX, 모든 SQLite 원본은 **수정하지 않았다**. 이번 68종의 기존 활성/비활성·최종 인증 비트는 0건 변경.
4. 평면도 렌더러에는 새 자료를 자동 합성하지 않았다. 향후 시각적 정의 우선순위의 소비 대상으로 이 오버레이를 사용할 수 있지만, 마인크래프트 방향/기능 변환은 별도 검증 필요.
